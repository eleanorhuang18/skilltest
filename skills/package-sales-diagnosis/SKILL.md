# package-sales-diagnosis

## 目标

对一个指定套餐（`family`，可加 `brand`）给出可证伪的诊断：**卖不动是不是真的、掉在哪一层、最可能的原因排序、下周该做什么**。结论必须带证据，不能只给现象。

## 适用与不适用

- 适用：单一套餐族的表现下滑、增长停滞、明显低于同门套餐。
- 不适用：全公司/全组合收入下滑（用运营统计类 skill）、新品定价与资费设计（属决策，不是诊断）、已确定原因只需执行方案。

## 输入

| 输入 | 必填 | 说明 |
| --- | --- | --- |
| 套餐族 `family` | 是 | 用户口语名要映射到库内 `family` 拼写，映射不上就列出候选让用户确认 |
| 时间范围 | 否 | 默认最近一个完整自然季度，对比上一季度；有同比再补同比 |
| 对比对象 | 否 | 默认同 `brand` 收入相近的 2–3 个套餐族 |
| 区域/渠道 | 否 | 用户点名了就单独看，没点名就全量拆 |

## 口径（先读，避免说错话）

数据源 `xlsmart-pg` 只读，**没有订单量字段**。所以"卖不动"只能用代理指标定义，报告里必须写明这是代理口径：

| 库字段 | 含义 | 用法 |
| --- | --- | --- |
| `ra_net` | 净收入 | 主指标，排序与增长的基准 |
| `rgb` | 用户月数 | 规模验证；**不是**去重用户数 |
| `mb_data` | 流量 | 使用强度 |
| `mb_5g` | 5G 流量 | 结构指标 |
| `swep` | 含义待确认 | 未确认前不用于结论 |

派生指标：代理 ARPU = `sum(ra_net) / sum(rgb)`；5G 占比 = `sum(mb_5g) / sum(mb_data)`。
禁用：把 `ra_net` 当订单收入、把 `rgb` 当销量、用 `family=OTHERS` 推断具体套餐。

## 步骤

1. **确认"卖不动"成立。** 四把尺子同时看：环比（本季 vs 上季）、同比（有数据才用）、目标完成率（有目标才用）、同门对比（同 `brand` 收入相近的 2–3 个族）。四把里至少两把为负才叫卖不动；只有一把为负就如实说明"属于正常波动"。完成条件：给出一句话判定——真下滑 / 结构性下滑 / 只是波动。

2. **看萎缩的形状。** 按 `region_9` 和 `channel` 分别拆当前季与上季，算两件事：
   - 贡献度：`ΔR_i / ΔR_total`，找出"谁把总量拖下去的"；
   - 集中度：该套餐前两大区域/渠道的收入占比，超过 50% 即为集中风险。
   完成条件：明确回答"是全面下滑还是局部塌方"，并列出贡献最大的两个对象。

3. **拆四层，找主矛盾。** 同时看规模、变现、使用、结构：

   | 现象 | 指向 |
   | --- | --- |
   | `rgb` 降、ARPU 稳 | 拉新不足或流失，渠道/覆盖问题 |
   | `rgb` 稳、ARPU 降 | 降档、折扣、权益缩水 |
   | 两者同降 | 产品力或价格竞争力问题 |
   | 流量升、ARPU 降 | 变现风险，用量与收费脱节 |
   | 5G 占比显著低于同门 | 结构落后，终端或网络覆盖制约 |

   完成条件：指出唯一主矛盾层，并说明其他三层为什么不是主因（各一句）。

4. **归因排序。** 按 `references/diagnostic-dimensions.md` 的六类逐一过：产品力、价格竞争力、渠道、区域、客群匹配、执行落地。每条给"判断依据 + 数据支持/待验证"。数据能证实的排前面，纯假设必须标"待验证"。完成条件：输出 3 条以内的高置信归因，外加至多 2 条待验证假设。

5. **反证。** 至少排除两个替代解释：大盘季节性（全组合同期是否也降）、同门普跌（同品牌其他族是否同幅下降）、口径变化（区域/渠道拼写或统计范围是否变过）。完成条件：每条反证给出数据，不能只写"已排除"。

6. **出报告。** 按 `references/report-template.md` 输出一页纸：结论先行、证据表、归因排序、动作清单、验证窗口。动作要落到岗位和指标，例如"西爪哇传统 SP 渠道下周补 20 家门店物料，观察 2 周 rgb 环比"。完成条件：每条动作都有负责人角色、预期影响、验证指标、观察窗口。

7. **交代数据边界。** 结尾固定一句：本结论基于代理口径（无订单量），若需确认因果，需要补充资费表、竞品价格、渠道激励政策三类数据。

## 产出格式

一页纸，顺序固定：

1. **结论**（≤3 行）：卖不动的性质 + 主矛盾层 + 最主要的两个原因。
2. **证据表**：指标 / 本季 / 上季 / 变化 / 同门对比 / 判断。
3. **贡献分解**：区域和渠道各一张小表，标出拖累最大的两项。
4. **归因排序**：置信度（高/中/低）+ 依据 + 待验证项。
5. **动作清单**：动作 / 负责角色 / 预期影响 / 验证指标 / 观察窗口。
6. **边界说明**。

## 异常处理

| 情况 | 处理 |
| --- | --- |
| 查不到该 `family` | 列出同 `brand` 全部族名让用户选，不要猜测近似名 |
| 上一季度数据为零或缺失 | 不计算增长率，改用绝对值和份额描述，并注明"无基期" |
| 只有单月数据 | 明确说明样本不足，只给方向性判断，不出归因排序 |
| 查询失败 | 报告失败原因类别（连接/权限/超时），不暴露连接串，不编数 |
| 用户追问因果 | 说明本 skill 给的是相关性与排除了哪些替代解释，因果需实验或补充数据 |
