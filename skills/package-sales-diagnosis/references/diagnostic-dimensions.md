# 归因维度字典

六类归因，按"能不能用库内数据证实"排序使用。每条都要写明依据和置信度。

## 1. 产品力

看什么：资费档位是否处于主流区间、权益组合是否有吸引力、合约期是否过长、是否有明显短板（如流量少、限速、无 5G）。

库内可测：同门对比的 ARPU 与流量结构；若同门 ARPU 相近而本族流量显著低，可能是权益或网络体验问题。

不可测：资费表、权益清单 → 标"待验证"，需要产品资料。

## 2. 价格竞争力

看什么：同档位相对竞品贵多少、是否有隐性收费、促销是否到期。

库内可测：ARPU 的时间序列突变（促销结束常表现为单月断崖）；同门价格带对比。

不可测：竞品价目 → 需外部数据。

## 3. 渠道

看什么：渠道覆盖（门店数、代理活跃数）、渠道产能（单店产出）、渠道政策（酬金、结算周期）、线上入口流量。

库内可测：`channel` 维度的收入与 `rgb` 变化、单渠道贡献度、渠道集中度、渠道间此消彼长（可能是内部搬家而非真流失）。

判断要点：单渠道塌方 + 其他渠道平稳 = 渠道问题；全渠道同幅下滑 = 不是渠道问题。

## 4. 区域

看什么：区域覆盖、竞品强度、网络质量、区域促销活动。

库内可测：`region_9` 维度的贡献度、区域集中度、区域间增长率离散度（标准差大 = 局部问题）。

判断要点：少数区域贡献了大部分降幅 = 区域性问题；降幅在各区域均匀 = 全局性问题。

## 5. 客群匹配

看什么：目标客群（学生/务工/家庭/银发）与该套餐定位是否错配、`brand` 子品牌定位是否重叠。

库内可测：同 `brand` 内各族的规模与 ARPU 结构；若新族上市后老族同幅下降，可能是内部替代。

不可测：客群标签 → 需用户画像数据。

## 6. 执行落地

看什么：一线是否在推（话术、培训、考核）、物料是否到位、系统是否可办理、库存/卡品是否断供。

库内可测：几乎不可测，只能通过"渠道/区域局部塌方 + 无价格与产品变化"间接推断。

判断要点：这类原因最容易被误判为"产品不行"。若数据上产品、价格、结构都正常，只剩执行可疑，就明确写"疑似执行问题，需一线核查"。

## 常见误判

| 误判 | 纠正 |
| --- | --- |
| 收入降 = 用户流失 | 先看 `rgb`；用户没少而收入降，是降档或折扣 |
| 流量涨 = 卖得好 | 流量与收入可能背离，看 ARPU |
| 单月下滑 = 趋势 | 至少看完整季度，单月常受结算日、促销周期影响 |
| 渠道降 = 客户跑了 | 检查其他渠道是否同步涨，可能是内部搬家 |
| 5G 占比低 = 网络差 | 也可能是终端渗透或套餐未含 5G 权益 |
