# SKILL.md 模板

复制下面整块，替换尖括号内容。删掉不适用的可选段，不要留空标题。

```markdown
---
name: <kebab-case-name>
description: >-
  <前 60 字符：用户会怎么说的触发场景，中文原话 + 英文原话>。
  Use when <用户可能的问法 1>、<问法 2>、<问法 3>.
---

# <name>

## 目标

<一句话：这个 skill 交付什么结果。写完自问：运营看完这句知道能拿它干嘛吗？>

## 适用与不适用

- 适用：<具体场景>
- 不适用：<容易误触发的相邻场景> → 应该用 <另一个 skill 或直接人工处理>

## 输入

| 输入 | 必填 | 说明 |
| --- | --- | --- |
| <参数/业务对象> | 是 | <从用户话里怎么取；缺失时怎么问> |

## 步骤

1. **<动作名>。** <具体命令或判断>。完成条件：<可检查的结果>。
2. **<动作名>。** …。完成条件：…。
3. **<动作名>。** …。完成条件：…。

> 步骤里出现表名、字段名、指标口径时，必须能在 `references/` 找到出处，或标注「待业务确认」。

## 产出格式

<固定结构：表格列名 / 报告小节 / 文件路径与命名。给出一个最小示例。>

## 口径与边界

- <指标定义，例如 ARPU = 某周期收入 / 平均在网用户数>
- <数据范围，例如 只取完整自然季度>
- <只读约束、脱敏要求>

## 异常处理

| 情况 | 处理 |
| --- | --- |
| 数据为空 | <说什么，不要编数> |
| 查询失败 | <报什么，不要暴露连接串> |

## 更新记录

- YYYY-MM-DD 初版
```

## 写作要点

- 步骤是给执行者看的动作序列，不是功能罗列。每步都能被"做完了吗"检验。
- 一个 skill 只解决一类问题。出现"顺便还可以…"就说明该拆。
- 示例数据要真实量级（月租几十元、ARPU 几十元、用户数万级），不要 1、2、3。
- 纯流程类 skill 不需要 `scripts/`；有确定性计算或取数逻辑时才加脚本，并在步骤里写明确切调用方式。
